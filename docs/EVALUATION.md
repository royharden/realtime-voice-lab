# Evaluation source and evidence handoff

This is unexecuted construction source. No task plan, audio fixture, result, calibration, soak or live comparison was run to create this document. `voicelab.evaluation` prepares a prospective plan and joins saved evidence into the **existing** `voicelab.reporting.write_report` pipeline. It does not launch browsers, speak, call providers, issue custody releases or establish product acceptance.

## Prospective paired design

`create_trial_plan(request)` and `scripts/run_evaluation.py plan` produce a deterministic, hash-pinned schedule from a caller-supplied integer seed. The request contains `run_id`, `seed`, exactly eight distinct `families`, two distinct `speakers`, one `network_profile`, pinned `models` for V/C/K, `fixture_cells` with one `{family,speaker,fixture_id}` per cell, `fault_schedules` keyed by family, and `turns_per_task` (1–8, default eight). Each fault action has a named `kind` and bounded integer `turn_position`. Driver owners define the supported action names and must refuse unsupported ones.

- Clean: two pairs per family/speaker cell (32), plus one extra pair per family with alternating speakers (eight). The extra repeats are fixed before execution.
- Fault: one pair per family, alternating speakers (eight), with the same frozen action schedule applied to both arms.
- Each cohort separately randomizes an exactly balanced AB/BA order (A=V, B=C): 20/20 clean, 4/4 fault. V/C tasks run adjacently in their declared order; the harness must retain same-window execution evidence.
- Every pair also schedules one separate K control on the same stimulus and fault conditions. K never participates in the V/C pair difference or AB/BA count. Total: 48 paired comparisons, 96 V/C arm-tasks and 48 K tasks.
- Each task has prespecified logical-turn slots (at most eight). Unused slots require an explicit `not_started` record; absence is unknown. Retrying transport retains its logical-turn identity and adds new attempt IDs. Do not recycle IDs for a new logical turn.

The selected network profile is a separate cohort. Repeat planning under a new run for other network/model/mode cohorts; never pool them. Fifty-ms each-direction application delay and forty-ms each-direction plus seeded 2% eligible-message drop are synthetic diagnostics, not observations about packet loss. This planner does not create those conditions.

The plan contains ordered `tasks`, `pairs`, canonical `turn_assignments`, `scheduled_turns` and `scheduled_tasks`. Tasks expose `task_id`, `trial_id`, task-level `pair_id`, `arm`, `cohort`, `family`, `speaker`, `repeat`, `network_profile`, `model_version`, `fixture_id`, `fault_schedule`, `logical_turn_ids` and `control`. A turn's canonical `pair_id` adds its position, preventing the reporter from treating several turns in a task as duplicate paired arms. K turn pair IDs are null. No expected answer is included in the executable plan.

`plan_hash` is SHA256 of canonical sorted compact JSON plus LF for the plan without its `plan_hash` field. `validate_trial_plan` reconstructs the same design from its embedded request and rejects changed ordering/membership/counts. Manifest `trial_plan_hash` pins this canonical digest. Artifact references separately hash **exact file bytes**. Changing a plan, model, threshold or fixture needs a new frozen cohort, not an in-place edit. CLI plan output uses exclusive file creation.

## Driver → assembler seam

The browser driver consumes the task plan; the assembler consumes a bundle pointing at saved artifacts under one explicit owned root. `artifacts` maps logical names to `{path,sha256,kind}`. Paths must be relative and resolve inside that root, including symlink resolution; hashes must match exact bytes. Audio also requires `approved_synthetic:true`. This flag is a retention prerequisite, not independent rights or custody proof. Hashes establish content binding, not who observed it.

Required names/kinds:

| Name | Kind | Content |
|---|---|---|
| `manifest` | `manifest` | Canonical RunManifest, explicit complete task/turn denominators |
| `plan` | `plan` | Frozen plan above |
| `fixtures` | `fixtures` | Fixture/license/provenance manifest |
| `trace` | `trace` | JSONL canonical VoiceEvent records |
| `ledger` | `ledger` | AttemptLedger summary/export including attempts/events |
| `observations` or `driver` | `observations` or `driver_observations` | Canonical TurnObservation sidecars, or raw D7 `driver.jsonl` converted here |
| `journal` | `journal` | Authority export with exact `run_id`; adjudicator binds its whole-file hash |
| `adjudication` (optional) | `adjudication` | External independent listening/journal rows |
| `freeze` (optional in dev) | `freeze` | Pre-exposure code/detector/scorer/plan/fixture pins |
| `release` (heldout only) | `release` | Externally verified independent custody release |

Additional named `audio` references bind stimulus/rendered WAVs and `calibration` references bind saved repeat lists. No raw audio is embedded in trace/result JSONL. Only explicitly referenced evidence is read; no directory discovery or heldout search occurs.

When `driver` is supplied, D5 converts raw events rather than expecting D7 to produce metrics. Ordered task/action/wire observations remain separate from server facts. In particular `turn_start_attempted`, `turn_driver_ended`, DOM state and session admission do not establish a started or successful logical turn. Malformed/missing hooks and sequence/clock ambiguity stay unknown. The converter refuses raw nonce/headers/authorization/PCM/transcript/text fields; producer telemetry must already be redacted. Original raw files are never rewritten.

Observed relay run IDs (including `mock-local`), server namespaces/session/boot IDs and wire turn IDs remain raw. Saved Ready envelopes and wire commits bind them to prespecified task/turn slots. The converter retains these aliases in `driver-correlations.json`, including actual transport and logical parents; the canonical result/attempt join uses the explicitly declared scheduled slot, never an overwritten source trace. ScheduledTurn's optional `observed_trial_id`, `observed_session_id`, `observed_boot_id` and `identity_evidence_reference` retain this separate verified mapping. Ambiguous or conflicting mappings fail/withhold instead of matching by a reused wire turn number alone. Session admission comes from actual Ready envelopes and is counted separately from logical-turn starts.

Recovery can have several transport terminals under one logical parent. Ordered start/terminal records survive in the correlation sidecar; earlier failed/interrupted attempts are not discarded. The final transport outcome does not reset the original logical deadline or erase prior cost. Browser `speech_end_ms` retains the earliest saved anchor for that logical parent; later retry timing is never rebased to a new zero. No browser anchor can be synthesized from driver/server nanoseconds. Observed controller duration uses explicit D4 `span_start_ns`/`span_end_ns`/`span_clock_domain` and boot identity; trace receipt timestamps cannot stand in for controller execution.

`TurnObservation` is defined in `evaluation/assembly.py`:

- Required `run_id`, `trial_id`, `logical_turn_id` bind the immutable assignment.
- `admission`: `started|refused|not_started|unknown`; `outcome` is a canonical terminal enum or null. Missing observation/terminal yields `missing_terminal`, never success. An admitted session is not automatically a started logical turn.
- `timing_domain`: `browser_performance_ms|unknown`; optional nonnegative finite `speech_end_ms`, `first_received_pcm_ms`, `first_nonsilent_render_ms` are driver-observed anchors. Subtraction is allowed only within that browser domain, never across server/provider clocks. Render time denotes the browser output timestamp estimate, not physical sound at an ear. The driver must supply the first non-silent rendered anchor, not scheduled/received audio time.
- Optional `input_audio_artifact`, `rendered_audio_artifact`, `calibration_artifact` are names in the bundle reference map. Missing/unapproved/hash-invalid audio gives unknown adjudication; it does not delete the turn.
- `retry_count`, `duplicate_count` are nonnegative integers; `stages` retain explicit stage/domain/observation data for canonical report analysis. A stage without valid same-domain anchors must remain unknown.

Whole-file trace integrity checks catch malformed canonical events, duplicate/reordered session/connection/domain sequences, nonmonotonic same-domain timestamps and producer integrity errors. Cross-run/unscheduled or wrong arm/trial trace data is rejected. Integrity failures invalidate timing/qualification rather than selectively dropping bad events. D4 owns canonical event/schema evolution; D7 owns raw browser measurements and observation emission. D5 owns joining them. These are source contracts; joined execution remains unverified.

## Fixture, freeze and custody gates

Fixture manifest shape is `{fixtures:[...]}`. Every referenced fixture has `fixture_id`, `split`, `wording_family`, `speaker`, `interruption_schedule`, `synthetic:true`, `audio_artifact`, exact `sha256`, `generator`, `generator_version`, `voice`, nonempty `settings`, actual `sample_rate`, and `license:{reviewed:true,reference,output_redistribution:true}`. The license reference must cover generator code/weights, voice and output rights under the eventual review. Public/upstream fixtures are dev-only. Selected family/speaker metadata must match the plan; input bytes must match the fixture digest. The gate compares the exact fixture-manifest file hash with `RunManifest.fixture_manifest_hash`.

The development corpus target is at least 12 wording families and four synthetic speakers; below-target dev inputs get an explicit coverage limitation. A paired plan selects eight/two from that corpus without claiming heldout status. The independent heldout corpus requires eight new families, two different speakers and unseen interruption schedules; intersections are checked **per dimension** against declared development rows.

Freeze `pins` must exactly match manifest `code_hash`, `build_hash`, `config_hash`, `schema_hash`, `fixture_manifest_hash`, `trial_plan_hash`, `fixture_seal`, plus canonical `thresholds_hash`, `endpoint_hash` and `onset_hash`. `frozen_before_exposure:true` is a required declaration whose validity still needs external evidence. An operator supplies the **expected** canonical freeze digest independently; the assembler never derives an approval pin from its own input and calls that approval. Missing/mismatched freeze leaves dev progress explicitly limited.

Heldout fails closed without an operator-injected `verify_release` callback. That trusted callback must establish actual nonauthor custody/lineage, frozen pre-exposure release and single-use authorization/redemption outside implementation-controlled files. It must not merely trust JSON booleans or verify a self-generated seal. The release must bind `freeze_hash`, `fixture_manifest_hash`, `candidate_hash`, `seal`, `single_use_authorized:true`, and a durable `reference`. The assembler checks bindings **before reading any heldout artifact**. Single-use bookkeeping/authentication belongs to the independently operated release authority; it is not implemented by an author-written local flag. No default trust callback, gold authoring or release issuer is supplied here. R4 tightens this seam: all protected artifact reads, including assembly metadata, require an actual guarded read context described below. The default CLI has no verifier and cannot unlock dev/private/heldout reads with a file flag.

## Independent adjudication and canonical assembly

### Manual-review consumer schema v1

This is a source interface for future approved review rendering, not a review dataset or appointment. D5 owns these records; a future D6 view may render them without inventing correctness. Packet creation never issues independent custody or acceptance.

- Packet: `{schema_version:1, kind:"manual_review_packet", packet_id, packet_hash, run_id, task_id, created_at, source_hashes, items, evidence_status:"unadjudicated", product_acceptance:false}`. `created_at` comes from the frozen manifest. `packet_hash` is the canonical content digest excluding itself. At most eight turn/response items per task; no inline audio, transcript or provider-generated answer.
- Item: `{item_id, bindings, artifacts, evidence_gaps}`. Bindings pin `code_hash`, `build_hash`, `fixture_manifest_hash`, `trial_plan_hash`, `run_id`, planned `trial_id`/`logical_turn_id`, actual `response_id` and observed identity refs, plus exact input/rendered audio, journal, trace, ledger and genuine-confirmation evidence hashes. Missing hashes stay null with explicit gaps. Audio references are approved synthetic artifacts only, resolving under the owned artifact root.
- Human submission: `{schema_version:1, packet_hash, item_id, actor_ref, appointment_ref, decided_at:<recorded ISO time with offset>, judgments:{spoken:"correct|incorrect|unknown", task:"correct|incorrect|unknown", confirmation:"correct|incorrect|unknown"}, reasons:[<closed reason enum>], task_terminal:<explicit canonical outcome|null>, supersedes:<prior record hash|null>}`. A view must start all choices unselected/unknown and require an actual human decision; it must never propose a correctness verdict from text/model output. Task completion is an explicit human field, not inferred from one correct turn.
- Stored decision: `{schema_version:1, kind:"manual_review_decision", sequence, previous_hash, submission, bindings_hash, actor_verification:"unverified|externally_verified", record_hash}`. The complete original is append-only and hash-linked; a correction names `supersedes` and never edits an old record. Canonical oracle export rechecks real external actor authority and original bindings; a stored verification label or claimed name cannot authorize itself.
- External custody import uses the existing freeze shape `{pins,frozen_before_exposure,issuer_actor_ref,appointment_ref,reference,...}` and release shape `{run_id,freeze_hash,fixture_manifest_hash,candidate_hash,seal,single_use_authorized,issuer_actor_ref,appointment_ref,reference,...}`. Exact externally supplied file/canonical digest pins and an operator-owned authority verifier are required. Separate wording-family, speaker and interruption split checks reuse the canonical split audit. No CLI flag, hash, issuer name, self-made seal or import receipt establishes independence.

Closed human reason enums: `evidence_consistent`, `wrong_spoken_slot`, `false_commitment`, `contradictory_confirmation`, `unrequested_booking`, `off_script`, `audio_missing`, `audio_ambiguous`, `confirmation_missing`, `journal_missing`, `trace_incomplete`, `binding_mismatch`, `not_reviewed`, `insufficient_evidence`, `superseding_correction`. Missing input/output audio or genuine explicit-confirmation evidence cannot become correctness. Actual W7/W8 actor appointment, nonauthor/parent/fork independence, rights and release authority remain external closed gates; coding actors cannot supply those verdicts.

Canonical typed source models are `ReviewPacket`, `ReviewItem`, `ReviewBindings`, `ReviewArtifact`, `DecisionSubmission`, `DecisionRecord` and `Judgments` in `evaluation/adjudication.py`. D6/D7 consumers should use these field names and closed enums. All packet artifacts are typed relative references, never URL strings or inline audio. A rendering consumer must use the approved owned-root/hash/rights boundary, not place an arbitrary packet path directly into a remote audio URL.

Exact packet hash v1: remove **only the top-level `packet_hash`** from the parsed original JSON; do not apply defaults or remove nested keys. Recursively sort object keys by Unicode code-point order (not locale and not JavaScript UTF-16 sort for supplementary characters), preserve array order, serialize with Python `json.dumps(sort_keys=True,separators=(',',':'),ensure_ascii=True,allow_nan=False)`, append exactly one LF, UTF-8 encode, SHA256, lowercase hex. String escaping is ordinary JSON with all U+007F and above escaped as lowercase `\uXXXX` UTF-16 units (surrogate pairs for supplementary code points). Packet v1 permits strings, booleans, null, arrays/objects and safe integers only, within ±9007199254740991; no floats, NaN, Infinity or lossy browser integers. This makes the browser digest reproducible. Decision `record_hash` excludes only itself; a playback `declaration_hash` excludes only itself and uses the same helper/domain.

ReviewArtifact's exact descriptor is `{path,sha256,kind,approved_synthetic?}`: relative owned path, lowercase exact-file SHA256, kind `audio|journal|trace|confirmation_evidence`; `approved_synthetic:true` is mandatory for audio. It does not declare container/rate/channels or authorize rights. Retention authority remains the existing `core.retention.RetentionManifest`: `synthetic`, `approved_input_sha256`, `retain_input`, `retain_output`, `approval_reference`, `input_rights_reference`, `output_rights_reference`, `manifest_reference`, `retention_until_utc`, `custody_reference`, `policy`. Its actual saved PCM metadata is 24000 Hz, mono, `signed_little_endian_pcm16`; an exact file hash is distinct from decoded/repacked media content. A browser must hash original bytes first.

`PlaybackDeclaration` is a separate **unverified local-view declaration**, not another oracle or retention approval: `{schema_version:1,kind:"manual_playback_declaration",packet_hash,item_id,role:"input_audio|rendered_audio|confirmation_audio",audio_hash,container:"wav|raw_pcm",media_type:"audio/wav|application/octet-stream",encoding:"signed_little_endian_pcm16",sample_rate:<integer>,channels:1|2,bits_per_sample:16,approved_synthetic:true,policy:"operator_custody_expiry",approval_reference,input_rights_reference:<string|null>,output_rights_reference:<string|null>,manifest_reference,custody_reference,retention_until_utc:<offset timestamp>,declaration_status:"unverified",product_acceptance:false,declaration_hash}`. The approval/rights/manifest/custody/expiry fields map directly to existing retention names; the declaration cannot create them. `validate_playback_declaration` checks shape/hash/packet/item/audio binding and role rights references only, not their authority. WAV media must correspond to WAV container; raw PCM uses application/octet-stream, not big-endian audio/L16. D6 must inspect verified original WAV headers or bound PCM declarations, frame alignment/rate/channels and actual byte digest before local playback, while keeping approval/identity/heldout gates closed. No declaration permits remote fetching, manual-capture retention or correctness inference.

Shared external purpose tags are exactly `manual_decision`, `custody_freeze`, `custody_release`, `cohort_authorization`, `live_authorization`, `fixture_rights`, `calibration_evidence` in `evaluation.trust.AuthorityPurpose/PURPOSES`. D7's additive API is `verify_gate_record(purpose,record,scope,expected_record_hash=...,authority=...,excluded_actor_refs=...)`. Record shape: `{schema_version:1,purpose,issuer_actor_ref,appointment_ref,reference,bindings:<exact expected scope>,...external issuance proof...}`; the canonical digest covers the entire record. Scope requires run/code/build/config/fixture-manifest/trial-plan identities; live additionally requires pricing-manifest hash and authorization reference, calibration requires actual calibration hash. Consumers must include their remaining frozen model/price/capability/budget/rights constraints in that exact scope and check actual data; the helper authenticates issuance, not experiment success. Bare caller flags, claimed names or matching hashes return no authorization without an actual operator-owned `ExternalAuthority`. Manual/custody use their existing canonical workflow and nonauthor-lineage exclusions, not this additive gate shortcut. No real verifier implementation or appointments are supplied.

### Manual workflow and external import source

`prepare_review_packet` reuses `assemble_evaluation` with no oracle and no report write. It selects one task, at most eight items, and uses manifest time rather than invocation time. Its items contain no expected-answer generator, transcript or default correctness. Missing source evidence remains an item with null bindings and gaps. `TurnObservation` may name a `confirmation_artifact` of kind `confirmation_evidence`: it binds task ID, journal/trace hashes, actual confirmation turn, challenge hash, state version, response epoch, slot ID and an approved synthetic confirmation `audio_artifact`/`audio_hash`. This metadata does **not** prove genuine affirmation; the real independent human must listen and judge it. `response_id` is retained from actual output/ACK metadata. All code/build/fixture/response/audio/journal/trace/confirmation bindings must match before the assembler admits an exported oracle row.

`append_decision` accepts only explicit validated submissions. The caller provides the recorded human time with an offset. No application timestamp manufactures a decision. A journal contains immutable `records/<8-digit-sequence>-<record-hash>.json`; each record hashes its body, previous hash, exact packet/item binding and original submission. First decisions have null `supersedes`; corrections name the exact current item record. The original never changes. Exclusive create plus an owned transient lock prevents competing append claims; a stale/foreign lock fails visibly and is never automatically deleted. The writer flushes/fsyncs new files. Crash/concurrency durability remains unexecuted. Readers/exporters validate the entire bounded hash/supersession chain and refuse unexpected, reordered, changed or partial records. Detecting a deleted valid suffix additionally requires an externally retained expected head; without it export stays unknown. They do not trust the stored `actor_verification` label. Packets are capped at eight items/512 KB metadata; journals at 10,000 records/16 KB per record.

`export_oracle` rechecks packet bindings, artifact bytes, the independently retained journal head and exact external human issuance/appointment on the latest record, keeping the original chain. Its authority scope includes the exact decision hash and head, so an old authentic decision is insufficient after a supersession. Missing audio/response/confirmation/journal/trace data, absent authority/head pin, explicit uncertainty reasons or contradictory choices produce unknown values. A superseding unverified claim cannot silently become a new correct result. Correctness comes only from real human choices; provider transcripts never enter the packet or oracle. Programmatically the function returns canonical oracle rows **and an in-memory verifier** for `assemble_evaluation(...,verify_oracle=...)`; that verifier accepts only the exact reauthenticated exported rows. No serialized boolean or CLI flag can recreate it. The existing assembler remains the sole oracle consumer and report generator remains unchanged.

`ExternalAuthority.verify(purpose,record,scope)` in `evaluation/trust.py` is an interface with **no implementation supplied**. The operator's separately appointed authority must authenticate exact issuance, real actor identity, role/scope and coding/parent/child/fork exclusions. `excluded_actor_refs` adds explicit known exclusions. A claimed human name, registry label, hash, local roster flag or implementation actor cannot qualify for W7/W8. Default CLI operations provide no authority and therefore cannot export authenticated correctness or unlock custody.

`import_custody` imports only caller-supplied public DTOs and exact descriptor/digest pins. It never opens private manifest/fixture/split/audio files or consumes a release. Enter its returned `PrivateExposureUse` under actual independent authority and durable local accounting before requesting a guarded reader. Canonical split audits then run behind that active context, and the existing gate acknowledges the same redeemed use without a second redemption. Neither a receipt nor an arbitrary callback authorizes private access. See the R4 boundary below.
