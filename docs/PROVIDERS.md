# Provider and mock boundaries

Mock remains the default. Live V/C source in `adapters/live.py` and `transport.py` is guarded by `validate_live_config`; absent/incomplete/expired manifests refuse before network operations. No approved manifests, actual credentials, selected available models/voices or certified prices are supplied. K refuses live mode until licensed fixed speech is available. The CLI remains mock-only; a later authorized operator must inject explicit live server settings.

The injectable default transport uses only `wss://api.openai.com/v1/realtime` and `https://api.openai.com/v1/audio/speech`, blocks redirects and caps time, frame/queue/output sizes. Native/STT session negotiation checks the returned model against its declared verified identity. Source uses pinned websockets14.1's redirect decision seam ([upstream source](https://github.com/python-websockets/websockets/blob/14.1/src/websockets/asyncio/client.py)); dependencies and behavior remain unexecuted. The transport obtains credentials only from an injected server-side callable at future dispatch. HTTP worker cancellation can leave a bounded in-flight read until its timeout; reservation liability remains unknown rather than claiming an external request was rolled back.

Required live configuration is `{mode:'live', run_id, models:{native,stt,tts}, voice, session_update:{native,stt}, manifests:{authorization,capabilities,pricing,rights,evaluation}}`. Only arm-relevant models/tariffs are required. `authorization` requires `approved:true`, `scope:'M6-live'`, reference, timezone-qualified expires_at and positive budget_usd exactly matching the ledger. `capabilities` requires verified/reference, manual_endpointing, sample_rate24000, exact supported_models, returned_models for WebSocket components, session_update_sha256, connection_metering:'no_charge_verified', plus native_cancel_truncate/response_metadata_echo for V or verified_voice for C. Session update hash uses sorted compact JSON and must explicitly disable turn detection with PCM/24k input. `pricing` requires reference/version/currencyUSD and per-component `{bound_usd,bound_basis,rates:{'<usage.dot.path>':'USD-per-unit'}}`. Unknown usage dimensions remain conservative liability. `rights` requires reference/approved/voice_output_redistribution; `evaluation` requires reference and custody/reviewer/offline_gate/calibration_gate references. These references are structural inputs, not self-issued approvals; the operator must verify their authority and provenance before activation. No placeholder live configuration passes these gates by default.

`credential_provider(component)->str`, optional transport injection and a trusted synchronous `confirmation_evidence(context)->literal True` are programmatic server-side interfaces. Confirmation context contains actual ephemeral PCM bytes/digests, sample rate, namespace, logical/transport turn, current epoch and authoritative slot/challenge/version. Missing/unevaluable evidence refuses confirmation; provider transcripts and tool arguments never establish assent. PCM is cleared after commit/cancel/close and never retained as a recording by these adapters. Public tool/TTS answers filter internal challenge/journal identifiers. Native response metadata fences old generation output; cancellation clears input and truncates only a known rendered item. A missing history identity or ambiguous live reconnect ends unrecovered. C resets its STT transport after interruption before accepting new audio, preserving task authority and fenced output.

The narrow parser in `adapters/providers.py` maps a documented subset of native audio deltas, final/partial input transcripts, function-call arguments, response terminals, truncation acknowledgement and errors. Native mock payloads traverse this parser; C mock transcript payloads traverse its transcription parser and TTS bytes traverse the raw PCM decoder. Outbound append, commit, cancel and rendered-sample cutoff truncation use serializer functions. Unknown event types/formats fail explicitly. This is source-level protocol construction, not a complete vendor SDK or a compatibility probe. Native mock tool proposals come from the same narrow lexical matcher used by C. Typed mock stimulus is not recognized speech.

Official OpenAI documentation consulted on 2026-10-23: [Realtime conversations](https://developers.openai.com/api/docs/guides/realtime-conversations), [Realtime transcription](https://developers.openai.com/api/docs/guides/realtime-transcription), [Text to speech](https://developers.openai.com/api/docs/guides/text-to-speech). The selected subset handles Base64 native PCM deltas and committed-item transcript events; the documented raw TTS PCM format is signed little-endian 16-bit/24 kHz. These documentation observations establish no account access, chosen available model/voice, usage tariff, cancellation guarantee, redistribution right or actual transport behavior.

Mock output is an 80 ms mathematically generated 440 Hz diagnostic tone, labeled at the UI, adapter and relay. It carries no spoken meaning. It must never pass spoken-answer adjudication. K uses this same diagnostic control until licensed fixed speech is supplied and reviewed. There is no generated speech asset or recording in the repository.

Before later live activation/admission: pin an actually supported native/STT/TTS model and voice, endpoint schemas and returned identities; verify manual endpointing, format negotiation, cancel/truncate/history consistency, usage units and enforceable output/context bounds; approve rights/retention and refreshed prices/budget; retain all charged attempts including cancellation/retry; complete licensed fixtures, calibration, fault/soak and independent custody/reviewer gates. A provider unable to meet matched endpoint/audio controls must be rejected or placed in a separately labeled unmatched diagnostic cohort. No silent substitute or proxy price certifies that gate.

Provider errors expose sanitized codes, never raw provider messages, keys or audio. Synthetic fixture data in `fixtures/wire/` is authored diagnostic data. Missing usage stays unknown; an empty completed response is not a correct answer. Reordering, duplicate provider events, missing/late usage and error-after-charge require integrated validation after construction mode closes.
